How I work

Not just code.Code that ships.

A model in a notebook is a guess. I care about the part after the demo — evaluation, guardrails, monitoring, and the boring plumbing that keeps an agent useful on day 300.

  • 01

    Start from the business problem

    Every system begins with the decision it improves and the metric that proves it.

  • 02

    Evaluate before you scale

    Test suites and evals come first, so quality is measured, not assumed.

  • 03

    Design agents to be governed

    Clear tools, clear boundaries, MCP and A2A patterns a whole enterprise can adopt.

  • 04

    Teach what you ship

    If I can't explain it in a 60-second Reel, I don't understand it well enough yet.
